# Symple Audio Splitter

mp3 / m4a の音声ファイルをブラウザだけで分割する PWA です。ファイルはサーバーに送信されず、すべての処理が端末内で完結します。

## 機能

- **分割線を自由に追加** — 波形をダブルクリック、または「現在位置に分割線を追加」で任意の数だけ分割線を置けます。分割線はドラッグで移動、上部の × で削除。
- **均等分割** — 指定した個数に等しい時間で分割。
- **無音検出で自動分割** — しきい値 (dB)、最短無音長、最短セグメント長を指定して無音区間の中央で分割。
- **オーバーラップ** — 各分割点の前後に指定ミリ秒だけ重ねて書き出し。
- **プレビュー再生** — 波形上でシーク、区間ごとの試聴、ループ再生。
- **波形表示＋ズーム** — ズームイン/アウト、全体表示、パン。
- **出力形式** — 入力と同じ形式が既定。MP3 / M4A (AAC) / WAV を選択可能。
- **品質設定** — 既定は「元のまま」。再エンコード時も元ファイルのビットレートを引き継ぎます。MP3 / AAC はビットレート指定、WAV は 16/24bit PCM・32bit float も選べます。

## 読み込みの高速化

初回読み込みでは PCM デコードを待たず、コンテナ解析だけで UI を出します。

| 工程 | 内容 |
| --- | --- |
| コンテナ解析 | 数 ms。m4a は `mdhd`、mp3 はフレームヘッダ、wav は `fmt` から長さ・レート・チャンネル・ビットレートを取得 |
| UI 表示 | 解析直後に操作可能。プレビュー再生は `<audio>` + Blob URL なので PCM 不要 |
| 波形 | 表示範囲ぶんだけ Worker で生成。範囲の先頭フレームへシークし、表示解像度に応じてフレームを間引く。ズーム・スクロールで足りない範囲だけ取り直す |
| 無音検出 | 全編の 10ms RMS を別 Worker でバックグラウンド生成。分割・書き出しを始めると停止する |
| PCM デコード | 再エンコードが必要になったときだけ実行。既定の「元のまま」では走らせない |

30 分 m4a の実測: 操作可能まで 0.08 秒、全体波形の描画まで 0.36 秒（従来は 8–10 秒ブロック）。
- **ファイル名** — `元のファイル名_01.mp3` のように連番で出力。
- **ZIP 一括ダウンロード** — 分割結果を 1 つの zip にまとめて保存。
- **PWA** — ホーム画面にインストール可能。オフラインでも動作します。

## 使い方

1. mp3 / m4a ファイルをドロップ（またはファイルを選択）。
2. 波形を見ながら分割線を追加するか、「均等分割」「無音検出」を使います。
3. 必要ならオーバーラップと出力形式・品質を設定します。
4. 「分割して書き出す」または「ZIPでまとめて保存」を押します。

ショートカット: `Space` 再生/停止、`S` 現在位置に分割線を追加。

## 処理の高速化について

| 経路 | 方式 |
| --- | --- |
| MP3 → MP3（品質「元のまま」） | フレーム単位でバイト列を切り出すだけ。**再エンコードなし**でほぼ即時 |
| M4A → M4A（品質「元のまま」） | AAC サンプル単位で切り出して mp4-muxer で再構成。**再エンコードなし** |
| WAV → WAV（品質「元のまま」） | PCM をフレーム境界でコピー。**ビット深度も元のまま**で、ビット精度は元と一致 |
| MP3（ビットレート指定） | lamejs によるエンコード（Web Worker で実行） |
| M4A（ビットレート指定） | WebCodecs の AAC エンコーダ + mp4-muxer（エンコーダはセグメント間で使い回し） |
| M4A（WebCodecs 非対応環境） | ffmpeg.wasm にフォールバック（初回のみ約 30MB を読み込み） |
| WAV（エンコード） | 既定は 24bit PCM。元ファイルのビットレートは、MP3 はフレームヘッダの平均、M4A はサンプル長から求めます |

デコードは再エンコード時のみ `decodeAudioData` を使い、元ファイルのサンプルレートを維持します。
波形ピークと無音検出用 RMS は Worker 内で WebCodecs により作るため、長い音源を読み込んでも UI が固まりません。

### ベンチマーク

`bench/` に再現可能な計測環境があります（Chrome を DevTools Protocol で操作）。

```bash
node bench/make-fixtures.mjs          # テスト音源を生成 (ffmpeg が必要)
npx vite --config bench/vite.config.ts --port 5199 &
node bench/run.mjs --label my-run --format m4a --bitrate original --splits 9 --repeat 3
node bench/e2e.mjs                    # 実際の UI を操作して分割結果を検証
```

3分ステレオ (44.1kHz) を10分割したときの書き出し時間:

| 条件 | 改善前 | 改善後 |
| --- | --- | --- |
| M4A → M4A（元のまま） | 1445 ms | **47 ms** |
| MP3 → MP3（元のまま） | 7061 ms | **28 ms** |
| M4A（192kbps 再エンコード） | 1404 ms | 1568 ms |

30分ステレオ (44.1kHz) を10分割したときの全体時間:

| 工程 | 改善前 | 改善後 |
| --- | --- | --- |
| デコード | 4243 ms | 4544 ms |
| 波形ピーク | 438 ms | 487 ms |
| **書き出し** | **16863 ms** | **232 ms** |
| 合計 | 21544 ms | **5263 ms** |

長いファイルではデコードと波形計算が支配的になるため、体感の改善は
「書き出しがほぼ消える」形になります。

### 試して撤回した改善

- **波形ピーク計算の Worker 化**: 30 分の音源ではチャンネル配列のコピーが
  数百 MB になり、438 ms → 1652 ms と逆効果でした。
- **Worker 内での `AudioDecoder` によるデコード**: Worker には
  `OfflineAudioContext` が無いため `decodeAudioData` は使えず、`AudioDecoder` で
  MP4 サンプルを直接デコードしてピークだけ返す方式を試しました。メインスレッドの
  ブロックは 397 ms → 43 ms に減りますが、デコード自体が遅く 30 分の音源で
  487 ms → 7283 ms と大幅に悪化するため撤回しました。

## 開発

```bash
npm install
npm run dev      # 開発サーバー
npm run build    # 型チェック + 本番ビルド
npm run preview  # ビルド結果の確認
npm run icons    # PWA アイコンの再生成
```

### 構成

```
src/
  audio/    デコード・分割計算・無音検出・各エンコーダ
  ui/       波形描画・再生・インストールボタン
  workers/  MP3 エンコード用 Web Worker
  main.ts   UI の組み立て
```

Service Worker (`sw.js`) はビルド時に Vite プラグインが生成し、ビルド成果物をプリキャッシュします。
